Enhancement One | CS 499 Computer Science Capstone

Artifact

The artifact selected for this enhancement is my final project from CS 330: Computational Graphics and Visualization. The application is a C++ and OpenGL Star Trek battle scene containing Federation and Klingon starships, a planet, starfield, photon torpedoes, textures, lighting, and an interactive camera.

Enhancement Overview

The original project successfully created the required three-dimensional scene, but much of its configuration and resource management was tightly coupled to the SceneManager. The purpose of Enhancement One was to improve the architecture, maintainability, extensibility, and defensive programming of the application without changing the appearance of the completed scene.

The enhanced version introduced a SceneObject model and reorganized the application into a more data-driven scene architecture. Scene objects are stored in a dynamic collection and processed through a common rendering path rather than being individually hard-coded inside the main RenderScene method.

Additional improvements included replacing fixed texture storage with a dynamic container, using smart pointers to make resource ownership clearer, correcting material lookup behavior, validating texture lookups, and improving cleanup and error handling.

Skills Demonstrated

This enhancement demonstrates object-oriented design, refactoring, C++ standard-library containers, RAII and smart-pointer resource management, defensive programming, OpenGL development, CMake, and evaluation of architectural trade-offs.

One of the most important lessons from this enhancement was recognizing the difference between software that simply functions and software that is structured to support future development. Rather than replacing code that already worked well, I concentrated on separating scene data from rendering behavior and correcting areas where the original design made future changes more difficult.

Course Outcomes

This enhancement primarily supports the course outcomes related to designing and evaluating computing solutions, applying well-founded software-development techniques, and developing a security mindset. Defensive resource handling, validation, and clearer ownership reduced several weaknesses identified during the original code review.

Reflection

Revisiting this artifact after completing additional coursework gave me a different perspective on the original implementation. When I first created the project, my main goal was making the scene work correctly. During the capstone enhancement, I approached the same project from the perspective of maintainability, extensibility, reliability, and future development.

The refactored architecture also provided the foundation for the later Algorithms and Data Structures and Database enhancements, demonstrating how software design decisions affect the ability to continue extending an application.
